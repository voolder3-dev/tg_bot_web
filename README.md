# Telegram Bot Dashboard

Универсальная веб-панель для поддержки через Telegram-бота. Она позволяет читать сообщения пользователей и отвечать им прямо из браузера.

**Общая панель:** https://voolder3-dev.github.io/tg_bot_web/

Каждый владелец подключает собственные ресурсы: Telegram-бота, backend на Render, базу PostgreSQL на Neon и отдельные секретные ключи. Данные разных владельцев не смешиваются: панель обращается только к тому backend, адрес которого ввёл пользователь.

## Как устроен проект

| Часть | За что отвечает |
|---|---|
| GitHub Pages | Общая статическая страница с интерфейсом панели |
| Render | Backend: API панели, связь с Telegram и обработка webhook |
| Neon | PostgreSQL: список чатов и история сообщений |
| Telegram Bot API | Доставка сообщений от пользователей и отправка ответов |

**Важно:** GitHub Pages не запускает Node.js и не хранит базу. На GitHub Pages находится только HTML/CSS/JavaScript интерфейс. Node.js-сервер работает отдельно на Render.

### Возможности

- список чатов, в которых пользователи написали боту;
- просмотр истории сообщений;
- отправка ответов от имени бота;
- автоматическая регистрация webhook при подключении;
- обновление чатов и сообщений примерно каждые 10 секунд.

Бот не может получить список всех людей, которые просто открыли его профиль. Пользователь должен открыть бота, нажать **Start** и отправить сообщение.

# Публикация общей панели на GitHub Pages

Этот раздел нужен владельцу общего репозитория. Пользователям, которые подключают собственный backend, повторять эти действия не нужно.

1. Открой репозиторий на GitHub.
2. Перейди в **Settings → Pages**.
3. В разделе **Build and deployment** выбери **Deploy from a branch**.
4. В качестве ветки выбери **main**, а папки — **/(root)**.
5. Нажми **Save** и дождись публикации.
6. Открой адрес: https://voolder3-dev.github.io/tg_bot_web/

После изменения файла index.html GitHub Pages опубликует новую версию автоматически. Иногда обновление занимает несколько минут; если браузер показывает старую страницу, обнови её без кэша.

Если ты публикуешь собственную копию интерфейса на другом GitHub Pages-адресе, укажи origin этой страницы в ALLOWED_ORIGIN на своём Render. Как правильно записывать origin — смотри шаг 4.

# Полная установка своего бота и сервера

Делай шаги по порядку. Для каждого собственного бота нужен свой Render Web Service, своя база Neon и свои секретные значения.

## 1. Создай бота в BotFather

1. Открой Telegram и найди официального бота [@BotFather](https://t.me/BotFather).
2. Отправь команду:

~~~text
/newbot
~~~

3. BotFather попросит придумать отображаемое имя бота. Например: SilverSMP Support.
4. Затем придумай username. Он должен быть уникальным и заканчиваться на bot, например SilverSMPHelpBot.
5. BotFather выдаст **токен бота**. Скопируй его и сохрани в надёжном месте.

Токен — это секретный пароль от управления ботом. Не отправляй его посторонним, не вставляй в HTML/JavaScript, README, GitHub Issues, скриншоты или публичные сообщения. В проект он попадёт только в переменную окружения Render на шаге 4.

### Как поставить аватарку боту (необязательно)

1. В BotFather отправь /mybots.
2. Выбери своего бота.
3. Открой **Edit Bot → Edit Botpic**.
4. Отправь готовое изображение.

Можно также использовать команду /setuserpic и выбрать нужного бота.

---

## 2. Создай базу в Neon

1. Открой [Neon](https://neon.tech/) и зарегистрируйся.
2. Создай новый проект PostgreSQL.
3. Выбери регион. Желательно выбрать регион недалеко от Render-сервера.
4. Открой проект и нажми **Connect**.
5. Выбери базу и роль, которые Neon предлагает для подключения.
6. Скопируй **pooled connection string** — строку подключения с pooling (обычно в ней есть hostname с -pooler).
7. Сохрани строку как секрет. Она понадобится в Render как DATABASE_URL.

Не публикуй эту строку: в ней находятся данные для доступа к базе.

**Не нужно вручную создавать таблицы.** При первом успешном запуске backend сам создаст таблицы chats и messages, а также необходимые индексы. Не запускай SQL для удаления таблиц: это удалит сохранённую переписку.

---

## 3. Подключи репозиторий к Render

1. Открой [Render](https://render.com/) и зарегистрируйся или войди.
2. Нажми **New → Web Service**.
3. Подключи GitHub, если Render ещё не подключён к нему.
4. Выбери репозиторий voोलder3-dev/tg_bot_web.

   Если хочешь иметь собственную копию исходников, сначала сделай **Fork** репозитория в GitHub, а затем выбери свой fork в Render. Для обычного использования общей панели отдельный fork не обязателен: у тебя всё равно будет собственный Render-сервис и собственная Neon-база.

5. Укажи настройки сервиса:

   | Настройка | Значение |
   |---|---|
   | Name | Любое свободное имя, например my-telegram-support |
   | Runtime | Node |
   | Branch | main (или ветка твоего fork) |
   | Build Command | npm install |
   | Start Command | npm start |
   | Instance Type | Free или другой доступный тариф |

6. Создай Web Service.

Render начнёт сборку и запуск. Если переменные окружения ещё не добавлены, первая попытка запуска может завершиться ошибкой о недостающих переменных. Это ожидаемо: добавь их на следующем шаге и запусти Deploy ещё раз.

После создания сервиса Render покажет публичный адрес примерно такого вида:

~~~text
https://my-telegram-support.onrender.com
~~~

Скопируй адрес. Для панели нужен именно основной HTTPS-адрес — без /api, /health и других путей.

## 4. Добавь переменные окружения

Это обязательный шаг. Без всех пяти переменных backend не запустится.

1. Открой свой Web Service в Render.
2. Перейди в **Environment**.
3. В разделе **Environment Variables** добавь переменные:

| Имя переменной | Что вставить |
|---|---|
| BOT_TOKEN | Токен от BotFather из шага 1 |
| DATABASE_URL | Pooled connection string из Neon из шага 2 |
| ADMIN_API_KEY | Твой собственный длинный случайный ключ для входа в панель |
| WEBHOOK_SECRET | Другая случайная строка для проверки webhook от Telegram |
| ALLOWED_ORIGIN | https://voolder3-dev.github.io |

### Как правильно создать ключи

ADMIN_API_KEY и WEBHOOK_SECRET — это **два разных секрета**. Не используй токен бота вместо одного из них и не копируй один и тот же текст в оба поля.

Можно создать случайную строку на своём компьютере с помощью Node.js. Открой терминал и выполни команду:

~~~bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
~~~

Скопируй результат для ADMIN_API_KEY, затем выполни команду ещё раз и используй второй результат для WEBHOOK_SECRET. Не публикуй полученные строки.

Если Node.js на компьютере ещё не установлен, создай эти значения с помощью надёжного генератора случайных паролей. Не используй короткие, очевидные или одинаковые значения.

### Важная настройка ALLOWED_ORIGIN

Это одна из самых частых причин ошибки подключения.

Для общей панели проекта значение должно быть **точно таким**:

~~~text
https://voolder3-dev.github.io
~~~

Правила:

- указывай только origin сайта;
- не добавляй завершающий слеш;
- не добавляй путь /tg_bot_web/;
- не добавляй адрес Render;
- не ставь *.

Например, это **неправильно**:

~~~text
https://voolder3-dev.github.io/tg_bot_web/
~~~

А это **правильно**:

~~~text
https://voolder3-dev.github.io
~~~

Если ты используешь собственную копию frontend на другом домене, вместо примера укажи origin именно своей опубликованной страницы — схему и домен, без пути.

После добавления всех пяти переменных нажми **Save Changes**. Render перезапустит сервис или предложит Deploy. Дождись завершения сборки и статуса **Live**.

## 5. Запусти сервер и подключи панель

### Сначала проверь сервер

Открой в браузере свой адрес Render с путём /health. Например:

~~~text
https://my-telegram-support.onrender.com/health
~~~

При успешной работе должен появиться ответ примерно такого вида:

~~~json
{"ok":true,"service":"telegram-dashboard-api"}
~~~

Если вместо этого появляется ошибка, смотри раздел [Частые ошибки и решения](#частые-ошибки-и-решения).

### Теперь подключи общую панель

1. Открой https://voolder3-dev.github.io/tg_bot_web/.
2. В поле **Адрес сервера Render** вставь основной адрес своего сервиса, например https://my-telegram-support.onrender.com.
3. В поле **Ключ доступа** вставь значение ADMIN_API_KEY, которое ты сам добавил в Render.
4. Нажми **Подключиться**.

Панель проверит ключ через /api/session. Если всё правильно, откроется интерфейс со списком чатов.

**Не вставляй в поле ключа токен BotFather, пароль от Neon или значение WEBHOOK_SECRET.** Для входа нужен только ADMIN_API_KEY.

При успешном входе панель автоматически отправляет backend запрос на регистрацию webhook в Telegram. Если регистрация webhook не удалась, панель может всё равно открыться, но входящие сообщения не будут поступать, пока проблема не будет исправлена.

Ключ и адрес сервера сохраняются в sessionStorage текущей вкладки браузера. Они не записываются в URL и удаляются при выходе или закрытии вкладки. Не подключай панель на чужих и общедоступных компьютерах.

---

## 6. Проверь входящие и исходящие сообщения

1. Открой своего бота в Telegram по его username.
2. Нажми **Start** или отправь команду /start.
3. Напиши боту обычное тестовое сообщение, например: Привет!
4. Вернись в веб-панель.
5. Подожди обновления списка (обычно до 10 секунд) или нажми **Обновить**.
6. Открой появившийся чат и проверь, что входящее сообщение видно в истории.
7. Напиши ответ в поле внизу и нажми **Отправить**.
8. Проверь Telegram: ответ должен прийти от твоего бота.

Если обе проверки прошли, базовая связка Telegram → Render → Neon → панель и отправка ответа из панели работают.

# Частые ошибки и решения

Проверяй пункты по порядку — чаще всего причина в одной неверной переменной или в том, что сервис ещё не закончил запуск.

### 1. Render показывает статус Failed или сервер не запускается

**Причина:** backend не получил одну или несколько обязательных переменных окружения.

Проверь, что в Render → **Environment** добавлены все пять переменных: BOT_TOKEN, DATABASE_URL, ADMIN_API_KEY, WEBHOOK_SECRET и ALLOWED_ORIGIN.

Проверь написание имён, отсутствие лишних пробелов и то, что значения не пустые. После сохранения переменных дождись нового Deploy. В **Logs** найди сообщение об ошибке запуска.

### 2. Первый запрос долго загружается, а панель будто зависла

**Причина:** бесплатный Web Service Render может засыпать после периода бездействия. Первый запрос после простоя будит сервер, поэтому подключение иногда занимает заметное время.

Что делать:

1. Проверь, что сервис в Render не показывает Failed.
2. Открой /health своего Render-адреса.
3. Дай сервису время запуститься и повтори подключение.

Это не обязательно означает, что код сломан. После пробуждения последующие запросы обычно работают быстрее.

### 3. Ошибка «Этот адрес сайта не разрешён сервером»

**Причина:** значение ALLOWED_ORIGIN не совпадает с адресом опубликованной панели.

Для общей панели используй:

~~~text
https://voolder3-dev.github.io
~~~

Не добавляй /tg_bot_web/, слеш в конце или адрес Render. После исправления нажми Save Changes и дождись Deploy.

### 4. Ошибка «Неверный ключ доступа»

**Причина:** в панели указан не тот ключ.

Проверь:

- адрес Render в панели относится к нужному Web Service;
- в поле ключа вставлено значение именно ADMIN_API_KEY этого сервиса;
- ключ не перепутан с BOT_TOKEN или WEBHOOK_SECRET;
- при копировании не добавились пробелы в начале или конце.

Если ключ потерян, задай новое значение ADMIN_API_KEY в Render, сохрани и дождись перезапуска. Затем введи новый ключ в панели.

### 5. Панель открылась, но список чатов пустой

Это нормально, если боту ещё никто не написал.

Проверь:

1. Ты открыл именно своего бота, а не BotFather.
2. Нажал **Start** и отправил сообщение.
3. В Render сервис имеет статус **Live**.
4. В Render → **Logs** нет ошибок webhook или Neon.
5. В Neon используется строка подключения именно к твоему проекту.

Бот не может первым написать человеку, который ещё не начал с ним диалог.

### 6. Сообщения не приходят, хотя бот отвечает в Telegram

Входящие сообщения поступают в панель через Telegram webhook. После подключения панель сама вызывает регистрацию webhook.

Проверь:

- переменная WEBHOOK_SECRET задана и не пустая;
- Render-сервис доступен по HTTPS;
- в Render Logs нет ошибки при запросе регистрации webhook или обработке /telegram/webhook;
- ты отправляешь новое сообщение после настройки.

Если webhook не зарегистрировался, выйди из панели и подключись снова: при успешном подключении панель повторяет регистрацию. Не публикуй значение webhook-секрета при обращении за помощью.

### 7. Не отправляются ответы из панели

Проверь:

- выбран ли чат;
- не пустое ли поле сообщения;
- пользователь ранее нажал Start и написал боту;
- токен BOT_TOKEN относится к этому боту и не был отозван;
- Render Logs и уведомление в панели — там может быть текст ошибки Telegram API.

Если Telegram сообщает, что бот не может писать этому пользователю, попроси пользователя снова открыть бота и отправить ему сообщение.

### 8. Ошибка подключения к Neon или сервер не может создать таблицы

Проверь DATABASE_URL:

- строка скопирована из правильного проекта Neon;
- скопирована полностью, без кавычек и пробелов;
- используется pooled connection string из раздела Connect;
- проект Neon не удалён и база доступна.

После изменения переменной сохрани настройки и дождись перезапуска Render. Таблицы создаются автоматически при запуске backend.

### 9. В панели написано, что нужен HTTPS или адрес некорректный

В поле адреса вводи только основной адрес сервиса, например:

~~~text
https://my-telegram-support.onrender.com
~~~

Не добавляй /health, /api/session, /telegram/webhook, параметры после ? или путь. Для публичного Render-сервиса нужен HTTPS.

### 10. После изменения кода на GitHub ничего не поменялось

Если Render подключён к GitHub, проверь настройки автоматического Deploy. Если автоматическая публикация отключена, открой Render → свой Web Service → **Manual Deploy → Deploy latest commit**.

GitHub Pages и Render — разные части проекта: обновление index.html публикуется через GitHub Pages, а обновление server.js должно попасть на Render через Deploy. После публикации иногда нужно обновить страницу браузера без кэша.

## Безопасность

- Никогда не добавляй BOT_TOKEN, ADMIN_API_KEY, WEBHOOK_SECRET или DATABASE_URL в GitHub.
- Не публикуй секреты в скриншотах, логах, сообщениях и видео.
- У каждого владельца должны быть собственные токен, ключи, Render-сервис и база Neon.
- Не используй один ADMIN_API_KEY для разных владельцев.
- Не передавай ключ доступа посторонним: он позволяет управлять перепиской через твой backend.
- Используй панель только на доверенном устройстве. Ключ находится в хранилище текущей вкладки браузера и доступен JavaScript-коду этой страницы.
- CORS ограничивает браузерные запросы разрешёнными сайтами, но сам по себе не заменяет проверку ключа. Backend проверяет X-Admin-Key на защищённых API-маршрутах.
- Если токен BotFather или другой секрет случайно попал в публичный доступ, немедленно замени его и обнови соответствующую переменную окружения.

## Локальный запуск

Требуется Node.js 20 или новее.

1. Склонируй репозиторий или скачай исходники.
2. Установи зависимости:

~~~bash
npm install
~~~

3. Задай все пять переменных окружения так же, как в разделе 4.
4. Для локальной страницы добавь её origin в ALLOWED_ORIGIN. Если origins несколько, разделяй их запятыми. Не добавляй неизвестные сайты.
5. Запусти backend:

~~~bash
npm start
~~~

По умолчанию сервер слушает порт 3000 (или порт, который передал хостинг через PORT).
