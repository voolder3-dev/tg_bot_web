# Telegram Bot Dashboard

Универсальная веб-панель для переписки с пользователями Telegram-бота. Один общий интерфейс можно подключать к разным собственным серверам Render. У каждого владельца — свой Telegram-бот, свой сервер и своя база Neon.

**Общий адрес панели:** https://voolder3-dev.github.io/tg_bot_web/

## Как это устроено

- GitHub Pages — общий статический сайт панели.
- Render — отдельный backend-сервер каждого владельца. Он принимает Telegram webhook, проверяет ключ и отправляет ответы.
- Neon PostgreSQL — отдельная база каждого владельца, в которой хранятся только его чаты и сообщения.
- Telegram Bot API — принимает и отправляет сообщения от имени конкретного бота.

Панель не содержит общую базу пользователей. При подключении она обращается только к адресу Render, который указал пользователь.

## Возможности

- список чатов, которые начали диалог с ботом;
- просмотр истории сообщений;
- отправка ответов от имени бота;
- автоматическая регистрация webhook после подключения;
- обновление списка и сообщений каждые 10 секунд.

Бот не может увидеть людей, которые просто открыли его профиль. Пользователь должен нажать Start и отправить сообщение.

# Полная установка с нуля

## 1. Создай Telegram-бота

1. Открой Telegram и найди официального бота [@BotFather](https://t.me/BotFather).
2. Отправь команду `/newbot`.
3. Укажи имя и username для бота.
4. BotFather выдаст токен. Сохрани его в надёжном месте.
5. Не публикуй токен в GitHub, README, скриншотах или сообщениях.

Токен понадобится на шаге настройки Render.

## 2. Создай базу данных Neon

1. Открой [Neon](https://neon.tech/) и зарегистрируйся.
2. Создай отдельный проект PostgreSQL.
3. Выбери ближайший доступный регион.
4. Открой раздел подключения (Connect) и скопируй **pooled connection string**.
5. Сохрани строку как секрет. Не вставляй её в исходники.

Таблицы `chats` и `messages` сервер создаст автоматически при первом запуске. Существующие таблицы и записи не удаляются.

## 3. Создай backend на Render

1. Открой [Render](https://render.com/).
2. Нажми **New → Web Service**.
3. Подключи GitHub и выбери этот репозиторий: `voolder3-dev/tg_bot_web`. Если хочешь иметь собственную копию кода, сначала сделай Fork и выбери свой fork.
4. Укажи настройки:
   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free или другой подходящий тариф.
5. Создай Web Service и дождись первого успешного Deploy.

Render выдаст публичный адрес примерно такого вида:

`https://your-project.onrender.com`

Скопируй его — он понадобится для входа в панель.

## 4. Добавь переменные окружения Render

В своём Web Service открой **Environment → Environment Variables** и добавь переменные:

| Имя | Что указать |
|---|---|
| `BOT_TOKEN` | Токен, который выдал BotFather |
| `DATABASE_URL` | Pooled connection string из Neon |
| `ADMIN_API_KEY` | Твой собственный длинный случайный ключ доступа |
| `WEBHOOK_SECRET` | Отдельная случайная строка для проверки Telegram webhook |
| `ALLOWED_ORIGIN` | `https://voolder3-dev.github.io` |

Для `ADMIN_API_KEY` и `WEBHOOK_SECRET` используй разные случайные значения. Например, их можно сгенерировать локально командой Node.js:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Запусти команду два раза и используй разные результаты. Не используй пример из документации в качестве реального ключа.

**Важно про ALLOWED_ORIGIN:** указывай только origin сайта, без завершающего слеша и без пути `/tg_bot_web/`. Для общего сайта выше это именно `https://voolder3-dev.github.io`. Не ставь `*`: сервер должен принимать браузерные запросы только с разрешённого сайта.

Нажми Save Changes и дождись повторного Deploy. В Render переменные окружения не должны попадать в GitHub.

## 5. Открой общую панель и подключи свой сервер

Открой:

https://voolder3-dev.github.io/tg_bot_web/

На экране входа заполни два поля:

1. **Адрес сервера Render** — полный HTTPS-адрес своего Web Service, например `https://your-project.onrender.com`.
2. **Ключ доступа** — значение `ADMIN_API_KEY`, которое ты добавил в Environment на Render.

Нажми **Подключиться**. Панель проверит ключ через твой сервер и загрузит список чатов.

Ключ хранится в `sessionStorage` текущей вкладки браузера: он не записывается в URL и удаляется при закрытии вкладки или выходе. Не используй панель на чужих или общедоступных устройствах. Не передавай ключ другим людям.

## 6. Проверь Telegram

1. Открой своего бота в Telegram.
2. Нажми **Start** или отправь `/start`.
3. Напиши тестовое сообщение.
4. Вернись в панель и дождись обновления списка чатов.
5. Выбери чат, напиши ответ и нажми **Отправить**.

При первом успешном подключении панель попросит backend зарегистрировать Telegram webhook. Backend использует публичный адрес Render и значение `WEBHOOK_SECRET).

# Если что-то не работает

### Панель пишет, что сервер недоступен

- Проверь, что Render Web Service имеет статус **Live**.
- Открой `https://your-project.onrender.com/health`. Должен вернуться JSON с `"ok": true`.
- Проверь, что адрес введён целиком и начинается с `https://`.
- У бесплатного Render-сервиса может быть задержка при первом запросе после простоя.

### Ошибка «Этот адрес сайта не разрешён сервером»

Проверь `ALLOWED_ORIGIN` в Render. Для общей панели значение должно быть:

`https://voolder3-dev.github.io`

После изменения переменной дождись Deploy.

### Ошибка ключа доступа

Убедись, что в поле панели введено именно значение `ADMIN_API_KEY` с того же Render-сервера, адрес которого указан выше. Не путай его с `BOT_TOKEN` или `WEBHOOK_SECRET`.

### Чаты не появляются

- Убедись, что написал именно своему боту и нажал Start.
- Проверь Render Logs на ошибки подключения к Neon или обработки webhook.
- Убедись, что `DATABASE_URL` скопирован из правильного Neon-проекта.
- Проверь, что `WEBHOOK_SECRET` задан в Environment.

### Render сообщает об ошибке запуска

Проверь, что все пять переменных окружения добавлены без лишних пробелов и что Neon connection string действителен.

## Безопасность и данные

- Никогда не добавляй реальные токены, ключи и строки подключения в GitHub.
- Не отправляй секреты в скриншотах и не публикуй их в чатах.
- У каждого экземпляра backend должны быть собственные переменные окружения и собственная база Neon.
- Не используй один и тот же `ADMIN_API_KEY` для нескольких владельцев.
- Общая GitHub Pages-страница не получает доступ к базе напрямую: все операции с чатами выполняет указанный backend.
- API-ключ передаётся браузером backend по HTTPS в заголовке `X-Admin-Key`. Используй панель только на доверенном устройстве.

## Разработка

Требуется Node.js 20 или новее.

```bash
npm install
npm start
```

Для локального backend задай те же переменные окружения. Для локальной разработки можно добавить адрес локальной страницы в `ALLOWED_ORIGIN` отдельным значением, разделив origins запятой. Не добавляй публичные или неизвестные сайты.
